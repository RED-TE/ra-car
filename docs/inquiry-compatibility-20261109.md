# 기존 문의 공개 경로 보존

2026-11-03 성공 배포(run `41597249260`, commit
`a506b4cd29b46b1d9b6e944b46f50513fccca568`)에는 별도 문의 브랜치의 파일이
포함됐다. 해당 브랜치가 main에 합쳐지지 않아 이후 전체 사이트 배포에는
문의 경로 37개가 빠질 수 있었다. 이는 GitHub Pages 게시 시간 초과의 원인이
입증됐다는 뜻은 아니다. 게시 복구 중 확인된 별개의 경로 호환성 문제다.

## 보존한 내용

- `tests/fixtures/published-inquiry-paths-20261103.json`에 37개 경로와 원본 Git
  blob SHA를 고정했다.
- 이미지 30개와 CSS 2개는 원본 Git blob과 바이트가 같다. 합계 1,325,179바이트다.
- `/inquiry/steps.html`은 현재 `/inquiry/index.html`과 같은 렌트 전용 단계별
  신청폼을 제공한다. 두 파일의 동일성을 검사하므로 이후 폼 수정 시 함께
  갱신해야 한다.
- 예전 JavaScript 2개와 MJS 2개 경로는 현재 폼으로 연결한다. 예전 가격 조회·
  계산·접수 구현을 복구하지 않는다. 캐시된 이전 문서의 모듈 연결을 위해
  기존 export 이름은 유지하지만, 가격 목록은 비어 있고 접수는 거부한다.
- 이동 시 유효한 `ref`와 단일 광고 유입 값만 허용한다. 이름·전화·차량 선택·
  상품·기간·월납·선납·동의·외부 목적지는 전달하지 않는다. 잘못되거나 중복된
  명시적 추천 코드는 빈 `ref`로 전달해 저장된 다른 추천 코드가 대신 쓰이지
  않도록 한다.
- Node 정적 서버에는 이 37개 경로만 명시적으로 허용한다. 미등록 파일은
  계속 404이며 API와 쓰기 처리에는 변경이 없다.

현재 `inquiry/index.html`, `inquiry/catalog.mjs`, `inquiry/inquiry.mjs`는 변경하지
않는다. 기존 대표 가격, 리스 상품, 자동 입력·동의 또는 별도 Firebase 접수
흐름을 복원하지 않는다. 고객 데이터·저장 견적·DB는 대상에 포함되지 않는다.

## 로컬 검증

```sh
node --test tests/inquiry-compatibility.test.js tests/server-routes.test.js
npx playwright test tests/e2e/inquiry-compatibility.spec.js
```

단위 검사는 경로 보존, 자산 해시, 현재 폼 일치, 유입 값 제한, 기존 접수 거부,
이동 반복 방지를 확인한다. 서버 검사는 37개 정적 경로와 미등록 경로 차단을
확인한다.

브라우저 검사는 외부 요청을 모두 차단하고 합성 카탈로그·접수 응답만 사용한다.
375px 화면에서 현재 폼을 끝까지 진행해 렌트만 선택되고, 연락처와 동의를 새로
입력해야 하며, 동의 후 한 번만 합성 접수되는 것을 확인한다. 캐시된 실행 진입
3종은 안전한 유입 값만 보존해 이동하고 자동 접수하지 않는지 별도로 확인한다.
이 결과는 실제 고객 접수나 운영 게시 성공의 증거를 대신하지 않는다.
