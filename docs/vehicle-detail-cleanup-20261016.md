# 차량 상세 표시 정리 및 견적 실패 복구

## 적용 내용

- 차량 상세 로딩 화면의 자동차 아이콘과 아이콘 전용 간격 제거.
- 월 납입료 아래 주황색 옵션 추가 금액 배지 제거.
- 홈페이지의 `금융사 N곳 견적 비교하기` 링크 제거. 앱 최신 main에는 이 링크가 이미 없음.
- 옵션 선택, 검증된 월 납입료, 견적 조건 및 신청 흐름 유지.
- 견적 조회 실패 후 신청 버튼이 계속 준비 중으로 남는 상태를 수정. 실패 시 가격 영역의 오류 안내와 재조회 버튼을 표시하며, 재조회는 신청을 제출하지 않음.
- 확인된 월 납입료가 변경될 때 자리별 숫자가 회전하는 전환 효과 적용. 조회 중이거나 응답 검증 실패 시 이전 금액은 숨기고, 접근성의 동작 줄이기 설정에서는 즉시 최종 금액을 표시.
- 웹 공개 차량 캐시에 상품 구분 정보가 없으면 카탈로그를 새로 조회. 기존 견적, 고객 데이터 및 저장된 snapshot은 수정하지 않음.
- 스크롤 시 하단 버튼 위에 나타나는 월납 요약의 둥근 배경 및 테두리 제거. 좌측 항목명과 우측 금액만 표시하고, 중복된 '월' 및 금액 그림자 제거. 공간이 부족하면 항목명과 금액을 두 줄로 배치.

## 테스트 계약 정비

기존 웹 테스트 mock의 카탈로그 상품 정보, 견적 provenance 및 요청 조건을 현재 웹 검증 계약에 맞춤. 웹 전용 리스 전화 안내 문구의 기존 동작도 테스트에 반영함. 가격 검증을 완화하지 않았으며, 정비 후 위 테스트 전체 통과. 실패 응답과 조건 불일치 응답에서 이전 금액이 노출되지 않고 재조회가 가능한지 추가 검증함.

## 추가 관찰

## 카카오 웹 로그인 실패 수정

- 확인 원인: 설치된 Kakao Flutter SDK 2.0.0+1은 웹에서 `UserApi.loginWithKakaoAccount()` 및 `loginWithKakaoTalk()` 호출을 명시적으로 거부함. 웹 화면이 앱 전용 함수를 호출하고 있었음.
- 웹은 서버가 발급한 인가 주소로 이동하고 복귀 코드를 서버에서 교환하도록 연결. 앱 네이티브 SDK 로그인은 유지.
- S256 PKCE, 10분 만료 서명 state, 서버 복귀 주소 allowlist 및 브라우저 탭별 임시 저장소 검증 적용. 취소·위조·만료 콜백은 세션을 발급하지 않음.
- 인증 코드·state·verifier는 클라이언트 디버그 로그에서 마스킹. 클라이언트 시크릿은 API 서버에서만 사용하며 웹 빌드에 넣지 않음.
- 인증 복귀 URL의 코드를 제거하기 전 분석 도구 초기화를 건너뜀. 추천 코드 보관, 기존 계정 재사용 및 신규 계정 온보딩은 유지.
- 운영 API 공개 명세 조회 시 기존 `/api/v1/users/oauth/kakao`만 존재함. 새 `/web/start`와 `/web/complete` API를 먼저 배포하고 설정을 확인해야 함.
- API/앱 커밋: `311c1f7961f4f545ece19e2569b2be5c88315fa7`, PR: https://github.com/RECAREA/recar_app/pull/130.
- 로컬 검증: 서버 계정·인증·로그 검사 47 통과, 앱 전체 401 통과·2 건너뜀, 웹 Flutter 회귀 검사 91 통과, 홈페이지 검사 34 통과, 웹 release build 성공. 정적 분석 오류·경고 없음.
- 홈페이지 실제 브라우저 진입·추천 코드 보존 검사 14 통과, 크루 기존 기능 회귀 검사 82 통과. 이 검사는 실제 카카오 계정 동의나 운영 인증 성공을 대신하지 않음.
- 카카오 개발자 계정 로그인은 사용자가 직접 진행. 현재 AWS 계정에는 EC2 조회 권한이 없고 API 도메인은 Cloudflare 뒤이므로 기존 서버 접속 별칭 또는 원본 주소 및 배포 경로 확인이 필요. 권한·결제·DB 스키마는 변경하지 않음.
- 사용자가 PR 푸시·검사 통과 후 병합·운영 API 및 홈페이지 배포를 승인했음. 단, 실제 동의·세션 발급까지 검증하기 전 운영 로그인 정상화라고 보고하지 않음.
