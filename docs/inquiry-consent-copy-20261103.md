# 문의 랜딩 동의 오류·문구 수정

## 문제와 변경

원본 localhost 랜딩은 폼의 change 이벤트에서 버튼 상태를 검사한 뒤 공통 문서 이벤트가 하위 동의를 체크했다. checked 속성 대입은 새 change 이벤트를 만들지 않아 전체 동의가 체크된 상태에서도 마지막 신청 버튼이 비활성으로 남았다.

동의 동기화를 랜딩 UI의 capture 이벤트로 모아 하위 동의를 먼저 반영한다. 게시용 런타임의 중복 동의 처리는 제거하고 기존 제출 계약은 유지한다. 개별 동의의 부분 체크 표시와 추천 테스트에서 뒤로 이동 후 체크 상태도 복원한다. 마케팅 등 선택 동의는 신청 조건으로 요구하지 않는다. 전체 동의 자체로 신청하거나 다음 단계로 자동 이동하지 않는다.

상담 제목은 ‘갖고 싶은 그 차, 조건부터 비교하세요’, 테스트 초대는 ‘내 취향은 무슨 차를 탈까?’로 변경했다. 허위 순위·마감·혜택은 추가하지 않았다.

‘미리보기’ 문구를 제거하고 미전송 결과는 ‘입력 내용을 확인했어요 / 이 화면에서는 상담 신청이 전송되지 않았어요’로 표시한다. 접수번호·연락 약속·신청 완료는 검증된 실제 접수 응답에만 표시한다.

## 보호 범위

- 추천 규칙·가격·리스 금액 비노출·개인정보 문구·사업자 정보는 변경하지 않았다.
- 실제 접수증 확인, 중복 전송 방지, referral 귀속, 상담 금액 null 정책을 보존한다.
- 원본 sendFromLocal=false, 공통 코드, 메인과 다른 공개 경로는 유지한다.
- 별도 기능 브랜치 및 PR #36에서 진행하며 main 병합은 하지 않는다.

## 검증

- localhost5540에서 수정 전 전체/하위 checked=true, 버튼 disabled=true를 실제 클릭으로 재현했다.
- 수정 후 전체 체크·해제, 필수만 체크, 필수 해제, Space 조작에 버튼이 즉시 응답했다.
- 원본 PC1440·모바일375에서 사진 로드, 제목 줄바꿈, 가로 넘침 없음 확인.
- 원본 추천 테스트에서 12문항→상담→전체 동의→이전→복귀 동의 복원, 개인정보 Escape 후 테스트 유지, 미전송 결과 확인.
- npm run build: 154 통과. 최초 샌드박스 실행의 10실패는 localhost listen EPERM이며 허용된 재실행에서 모두 통과했다.
- 문의 랜딩 E2E: 14 통과. 전체 동의·키보드·선택 동의·상태 복원과 미전송/실접수 모의 분기를 검증한다.
- E2E의 API 응답과 접수는 격리된 모의 처리다. 실제 운영 문의·문자·인증 요청은 전송하지 않았다.

## 게시 범위

문의 전용 게시 절차는 main 72c007f9d61f92eb779fed26daf060b5e609cdf1을 그대로 보존하고 inquiry 폴더만 바꾼다. 직전 성공 게시본을 9bc51ff05e010dbd3b7c91152a4a036c0e8d5029로 고정 검증한 뒤 진행한다. 게시·원격 검사 결과는 GitHub 실행 기록으로 별도 확인한다. 이 문서의 로컬 검증만으로 운영 게시나 실제 접수 성공을 주장하지 않는다.
